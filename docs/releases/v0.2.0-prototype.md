# v0.2.0-prototype：实习投递版本

发布日期：2026-11-12。定位：C++17 软件事务内存与并发控制原型。
此版本在 `v0.1.0-prototype` 上补齐重试诊断、随机退避、并发回收修复、性能报告
和长时内存验证。固定版本入口：
[v0.2.0-prototype](https://github.com/ZephyrVia/CaSTM/tree/v0.2.0-prototype)。

## 本版内容

- 保留 OccSTM、WwSTM 两条并发控制路线，以及 EBR 与 TierAlloc 分配路径。
- 补齐失败原因和逐线程重试统计，实现有界随机退避。
- 修复已发布版本链边的并发读写、纪元推进与退休桶复用、线程槽位复用链边竞争。
- 归档修复后 108 次策略对照、60 分钟内存与回收验证及其原始数据和复现命令。

修复依据见 [BUG-09](../../BUG-09-OccSTM并发剪枝链边数据竞争.md)、
[BUG-10](../../BUG-10-EBR纪元推进与退休桶复用竞争.md)、
[BUG-11](../../BUG-11-EBR线程槽位复用链边竞争.md)。本次发布收尾更新版本入口与文档。

## 性能与内存结论

源码 `19d43f6` 在 20T、50R/50W、16 keys、8 操作/事务的代表配置中，jitter 三次
均有效，吞吐为 **906,055 ± 21,193 TPS**，p99 均值 **407.48 μs**。完整负载与
退化点见[性能报告](../performance/occ-ebr-performance.md)，不将单机微基准推广为业务 QPS。

长时验证源码为 `92a2605`，生产运行时与审计修复版本一致。两条分配路径各完成
2,400 个 worker 的创建退出，探针最终全部析构。TierAlloc 的 VmSize 初末窗口
中位数由约 1,768 增至 6,128 MiB，RSS 由约 77 增至 134 MiB；system 对照的
VmSize 约 1,446 MiB，未随批次增长。[长时报告](../performance/occ-memory-soak.md)
保存图表、原始计数与统计口径。

## 已知限制

- TierAlloc 在线程退出时保留部分 chunk；本版没有长期线程 churn 下默认分配器内存有界的结论。
- TSan 范围限于列出的 system allocator 用例；ASan 未启用完整泄漏检测。
- 一个 WwSTM 高冲突用例仍禁用，部分历史用例未纳入默认构建。
- 当前是单机内存事务原型，没有 WAL、崩溃恢复或网络存储服务；不宣称完整隔离级别、无饥饿或普遍吞吐领先。
